# wgctl REST API (v0.6.0)

> **Base URL:** `http(s)://<host>:<port>/api/v1`  
> **Porta padrão:** `7443`  
> **Content-Type:** `application/json` (request e response)  
> **Autenticação:** Bearer Token (todas as rotas exceto `/health`)

Headless REST API for managing WireGuard interfaces and peers via wgctl daemon.

Authenticate with a Bearer token generated by `wgctl daemon token create`.

All responses follow the envelope `{"success": true, "data": ...}` or `{"success": false, "error": {"code": ..., "message": ...}}`.

---

## Autenticação

Todas as rotas (exceto `/health`) exigem autenticação via token Bearer no header `Authorization` ou no query parameter `?token=<token>`:

```http
Authorization: Bearer <token>
```

Para gerar um novo token de acesso no servidor WireGuard:
```bash
wgctl daemon token create --name "meu-app" --expires 30d
```

---

## Formato de Resposta Padrão

Todas as respostas da API seguem um formato envelope uniforme:

**Sucesso (HTTP 2xx):**
```json
{
  "success": true,
  "data": { ... }
}
```

**Erro (HTTP 4xx / 5xx):**
```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Mensagem explicativa do erro"
  }
}
```

<a id="post-interfacesnamepeers"></a>
### `POST` /interfaces/{name}/peers

**Adicionar peer**

Adiciona um novo peer à interface.

**Modo managed** (padrão): o servidor gera o par de chaves. A chave privada do cliente é retornada uma única vez na resposta.

**Modo zero-knowledge**: forneça `public_key` com a chave pública do cliente. O servidor nunca vê a chave privada.

- **Autenticação:** Bearer Token obrigatório

#### Parâmetros

| Nome | Em | Tipo | Obrigatório | Descrição |
|:---|:---|:---|:---:|:---|
| `name` | `path` | `string` | Sim | - |

#### Request Body

- **Status:** Obrigatório
- **Content-Type:** `application/json`

| Campo | Tipo | Obrigatório | Padrão | Descrição |
|:---|:---|:---:|:---:|:---|
| `name` | `string` | Sim | `-` | Nome único do peer |
| `public_key` | `string` | Não | `-` | Chave pública do cliente. Se omitido, o servidor gera o par de chaves (modo managed). |
| `ip` | `string` | Não | `auto` | IP a alocar. 'auto' para o próximo livre. |
| `device` | `string` | Não | `device` | Tipo de dispositivo |
| `description` | `string` | Não | `-` | Descrição livre |
| `keepalive` | `integer` | Não | `25` | PersistentKeepalive em segundos |

#### Exemplo de Requisição (cURL)

```bash
curl -X POST "http://127.0.0.1:7443/api/v1/interfaces/{name}/peers" \
     -H "Authorization: Bearer $WGCTL_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{
       "name": "cliente-novo",
       "ip": "auto",
       "device": "laptop"
     }'
```

#### Respostas

- **HTTP `201`:** Peer adicionado com sucesso
- **HTTP `400`:** 
- **HTTP `401`:** 
- **HTTP `404`:** 
- **HTTP `409`:** Nome ou IP já existente
